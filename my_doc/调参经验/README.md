## 三条跨文档主线

1. **先测量再调参**：过拟合时先算 token/参数比，比值 ≥1 之前加正则都是隔靴搔痒。
2. **参数在哪，优化就在哪**：嵌入+输出占 89.3% → 砍词表立竿见影，缩层数是白费力气。
3. **硬件换了瓶颈也换了**：4GB 卡在显存，24GB 卡在 CPU 数据供给；不是同一套参数调大调小。

## 数据来源的三档标注

文档里的数字分三档，读的时候注意区分（各篇正文都有标注）：

| 档 | 含义 | 例子 |
|---|---|---|
| **实测** | 本机直接量出来的 | 句长分布、丢弃率、词频、参数量、断点字段验证 |
| **实测+外推** | 采样或小规模实测后按比例放大 | 2475 万对的总 token 数（20 万对采样 × 行数） |
| **推算** | 按公式或他人实测值算的 | 显存占用、时间账（旧配置 0.087 s/batch 直推） |

**推算的那部分在上线后要用实测替换**，尤其是时间账——`0.087 s/batch` 本身就取自 CPU 瓶颈状态，不能拿来规划 4090 上的耗时。
