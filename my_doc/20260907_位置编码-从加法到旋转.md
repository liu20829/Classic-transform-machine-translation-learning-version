## 第零章 数学工具箱:先花两分钟,后面全靠它

后面会出现矩阵和转置,这里把会用到的规则全部讲透,每条都配 2 维数字验证。你可以把下面的式子逐行抄下来用计算器验算,保证不再有天书感。

### 0.1 向量和转置是什么

**向量 = 一列数**。我们约定向量写成**列**:

```
x = ( 2 )        y = ( 1 )
    ( 3 )            ( 5 )
```

**转置 = 把列变行**(或者行变列),用右上角小 T 表示:

```
xᵀ = ( 2  3 )      一列变一行,数值顺序不变
```

### 0.2 点积的两种写法(为什么内积要转置左边)

两个向量的点积(内积)就是你熟知的"对应位置相乘再相加":

```
x · y = 2×1 + 3×5 = 17
```

写成矩阵形式时,左边的向量必须先转置成"行",才能和右边的"列"对齐相乘(行×列):

```
xᵀy = ( 2  3 ) · ( 1 )  = 2×1 + 3×5 = 17
                 ( 5 )

规则:矩阵乘法要求"左边矩阵的列数 = 右边矩阵的行数"。
xᵀ 是 1×2(一行两列),y 是 2×1(两行一列)→ 1×2 乘 2×1 合法,得 1×1 即一个数。
```

**所以见到 ⟨u, v⟩ 或 u·v 被改写成 uᵀv,只是换了记法,算的还是同一个数。**

### 0.3 矩阵乘向量:一个"变换器"

2×2 矩阵 M 乘向量 x,结果是另一个向量(对 x 做线性变换):

```
M = ( a  b )    Mx = ( a  b ) ( x₁ ) = ( a·x₁ + b·x₂ )
    ( c  d )         ( c  d ) ( x₂ )   ( c·x₁ + d·x₂ )
```

后面会用到一种特殊的 M——**旋转矩阵**,稍后专门讲。

### 0.4 最重要的规则:(Mx)ᵀ = xᵀMᵀ——转置要"反序"

如果先让矩阵 M 作用在向量 x 上(Mx),再对整个结果转置,会得到 xᵀ 在前、Mᵀ 在后的**顺序颠倒**的形式。这是死规则,数字验证一下为什么:

```
M = ( 1  2 )   x = ( 2 )        Mx = ( 1×2 + 2×3 ) = ( 8 )
    ( 0  1 )       ( 3 )             ( 0×2 + 1×3 )   ( 3 )

(Mx)ᵀ = ( 8  3 )

现在直接算 xᵀMᵀ 看是否相等:
Mᵀ = ( 1  0 )    xᵀMᵀ = ( 2  3 ) ( 1  0 ) = ( 2×1+3×2   2×0+3×1 ) = ( 8  3 )  ✓
     ( 2  1 )                      ( 2  1 )
```

两种算法得到同一个结果,所以规则成立。**直观理解:转置像"倒带"——本来顺序是"先 x 后 M",倒放就得"先 Mᵀ 后 xᵀ"。**

### 0.5 旋转矩阵 R(p) 和它的两个性质

**旋转矩阵 R(p) 的作用:把一个向量逆时针旋转 p 弧度**:

```
R(p) = ( cos p  −sin p )
       ( sin p   cos p )

验证 90°(p = π/2 ≈ 1.5708):R(π/2) = ( 0  −1 ),乘 (1,0)ᵀ 得 (0, 1)ᵀ
                                      ( 1   0 )
x 轴上的 (1,0) 被转到 y 轴上的 (0,1),确实是转了 90° ✓
```

两个性质后面推导会用到:

**性质 A:先转 b 再转 a,等于一次转 a+b**

```
R(a)·R(b) = R(a+b)

直观:顺时针不存在,"转 2 弧度再转 3 弧度" 当然等于 "一次转 5 弧度"。
```

**性质 B:旋转矩阵的转置 = 反向旋转**

```
R(p)ᵀ = R(−p)

验证(数字):p = 1 弧度
R(1)   = ( 0.540  −0.842 )        R(1)ᵀ = ( 0.540  0.842 )
          ( 0.842   0.540 )                 ( −0.842 0.540 )
R(−1)  = ( cos(−1)  −sin(−1) ) = ( 0.540  0.842 )   ← 与 R(1)ᵀ 相同 ✓
          ( sin(−1)   cos(−1) )   ( −0.842 0.540 )

几何解释:旋转矩阵是"正交矩阵",它的逆(转回去)= 转置(把矩阵翻个面)。
R(p) 把向量转 +p;要把它"转回去"就乘 R(p)ᵀ,也就是转 −p。翻面 = 反向。✓
```

## 第一章 问题设定:为什么注意力必须知道位置

自注意力对每个 token 的计算是:

```
query·key → softmax → 加权 value
```

**这里没有任何"顺序"概念**:如果"我爱你"和"你爱我"的输入表示相同,注意力打出的分数也相同。模型本质上是个"词袋"——除非我们在输入里显式告诉它"这个词是第几个"。

验证方法(可以自己做):训练一个不加位置编码的 Transformer,把测试句子的词序打乱,输出几乎不变——模型对语序失明了。

**结论:位置信息必须作为输入的一部分送进网络。** 剩下的问题是:怎么送?

## 第二章 第一招:加性正弦位置编码

### 2.1 先看"位置指纹表"长什么样

想象一个表格[N行,M列]:**每一行 = 一个token嵌入向量**,表格的列数 = 嵌入维度。这个表格叫 PE(位置编码矩阵),`PE[p]` 或 `PE_p` 就表示**第 p 行的内容**——注意这里记号就落地了:

> **PE_p 的下标 p 就是 token 的位置(第几个词),PE_p 是矩阵的第 p 行,是一个向量。**

为了让每行互不相同(否则位置无法区分),每一行用 sin/cos 生成。最小例子:4 个位置 × 4 列(两对同频的 sin/cos,频率 θ₁=1、θ₂=0.5):

```
         列0: sin(θ₁p)  列1: cos(θ₁p)   列2: sin(θ₂p)  列3: cos(θ₂p)
位置0    sin(0)=0.00   cos(0)=1.00     sin(0)=0.00    cos(0)=1.00    ← PE₀
位置1    sin(1)=0.84   cos(1)=0.54     sin(0.5)=0.48  cos(0.5)=0.88  ← PE₁
位置2    sin(2)=0.91   cos(2)=−0.42    sin(1)=0.84    cos(1)=0.54    ← PE₂
位置3    sin(3)=0.14   cos(3)=−0.99    sin(1.5)=0.997 cos(1.5)=0.07  ← PE₃
```

每一格怎么算的:先看**行号 p**(位置),再看**列号**(决定用哪个频率),代入 `sin(频率 × 位置)`。四个位置的四行互不相同 → 位置被唯一标记。

### 2.2 论文的原始公式:把表格"翻译"成数学

2.1 的表格只是把下面这个论文公式(Attention Is All You Need,3.5 节)逐格算出来摆在桌上。**论文公式定义了 PE 矩阵的每一个格子**:

$$
\text{PE}(pos,\ 2i) = \sin\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right)
$$

$$
\text{PE}(pos,\ 2i+1) = \cos\left(\frac{pos}{10000^{\,2i/d_{\text{model}}}}\right)
$$

意思是:矩阵的**第 pos 行、第 2i 列**填 sin(...),**第 pos 行、第 2i+1 列**填 cos(...)——即每对相邻的(偶,奇)列共享同一个括号里的值,只差 sin/cos。公式里每个符号逐项解释:

| 符号 | 含义 | 在本项目里 |
|---|---|---|
| pos | token 的位置(第几个词,从 0 开始数) | 就是 2.1 表的行号,0..51 |
| 2i、2i+1 | 维度下标:偶数列 / 紧邻的奇数列 | 列号 |
| i | 第几对同频维度,取值 0..d_model/2−1 | 0..127(共 128 对) |
| d_model | 嵌入维度 | 256 |
| 10000 | 频率基数(论文定的常数,可当超参调) | 10000 |
| 10000^(2i/d_model) | 第 i 对的"周期放大系数" | 决定这一列波形多快(见第五章) |

**对照 2.1 的表验证**:表格的列 0(即 2i=0):10000^0 = 1,格子 = sin(pos/1) = sin(pos)——表里列 0 填的就是 sin(0)、sin(1)、sin(2)、sin(3)。列 2(2i=2,d=4 时):10000^(2/4) = 100,格子 = sin(pos/100) = sin(0.5·pos)——表里 θ₂=0.5 就是这么来的。**公式和表格是同一件事,一个用符号、一个用数字。**

### 2.3 与全文的 θ 记号打通,并写成一行的 PE_p

论文式把"周期放大系数"放在分母(pos/10000^...);把它翻到分子,记:

```
θᵢ = 1 / 10000^(2i/d_model)      ← θᵢ = 每走一个位置相位转的弧度(角频率,见第五章)

论文式 ⟺  θ 记号:
PE(pos, 2i)   = sin( pos / 10000^(2i/d) ) = sin( θᵢ·pos )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) ) = cos( θᵢ·pos )
```

于是"第 pos 行整行"可以写成一个向量(把 pos 简写为 p):

```
PE_p = ( sin(θ₁·p), cos(θ₁·p),  sin(θ₂·p), cos(θ₂·p),  ...,  sin(θ₁₂₈·p), cos(θ₁₂₈·p) )
          ↑ 第1对 ↑               ↑ 第2对                      ↑ 第128对
```

**注意 p 在这里就是 2.1 表的行号**:给 p=6 代入,PE₆ 就是第 6 行的 256 个数。θᵢ 每列固定、随列递减(2i=0 时 θ=1 最快,2i=254 时 θ≈0.0001 最慢,详见第五章)。

### 2.4 与代码对号(完整版在第五章)

**源码**:`model/position_encoding.py:12-25`

```python
pos = torch.arange(seq_len)                     # pos = 所有行号 0..51
idx = torch.arange(0, dim_model, 2)             # idx = 偶数列下标 2i: 0,2,4,...,254
angles = pos / 10000 ** (idx / dim_model)       # 论文式的括号:pos / 10000^(2i/d_model)
pe[:, 0::2] = torch.sin(angles)                 # 偶数列(2i)填 sin
pe[:, 1::2] = torch.cos(angles)                 # 奇数列(2i+1)填 cos,与偶数列同频
```

`angles` 是 (52, 128) 的张量:行 = pos,列 = 2i。sin/cos 各填进偶/奇列后,`pe` 就是 (52, 256) 的 PE 矩阵——2.1 的表格、2.2 的公式、这里的代码,三处是同一张表。

### 2.5 加进模型:词向量 + 位置指纹

模型输入的第 p 个 token 不是只用词向量 w_p,而是:

```
实际输入向量 = w_p + PE_p
```

即"这个词的意思 + 它站在第几个位置"。代码在:

**源码**:`model/encoder.py:83`(decoder.py:98 同构)

```python
src = self.dropout((self.word_embedding(src) * self.coefficient)
                   + self.position_encoding(input_size, self.token_dim, self.device))
```

| 成分 | 作用 |
|---|---|
| `word_embedding(src)` | 查表取词向量 (N, 52, 256) |
| `* √d_model` | 放大词向量到与 PE(值域 ±1)可比量级,防止位置淹没词义 |
| `+ position_encoding(...)` | 加上位置指纹(2.2 的公式、2.1 的表格) |
| `dropout` | 正则 |

**位置编码本身没有参数**(sin/cos 是写死的函数),不参与训练。

## 第三章 理解钥匙:分配律展开——位置没被"加没了"

**你可能会问:词向量和位置向量一加,不就成了一个新的数(向量)了吗?那之后做乘法时,位置信息还提取得出来吗?**

答案:提取得出来。因为**点积(内积)是"线性"运算,它会自动把加进去的两部分重新拆开**。看推导,假设位置 6 的 token 和位置 7 的 token 做点积:

```
(w₆ + PE₆) · (w₇ + PE₇)
```

回忆小学分配律 (a+b)(c+d) = ac+ad+bc+bd,这里完全一样(点积对每个维度分别乘再加,分配律逐项成立),展开成四项:

```
= w₆·w₇          ← ①纯词义:这两个词本身像不像
+ w₆·PE₇          ← ②词义 × 对方位置:混合项
+ PE₆·w₇          ← ③位置 × 对方词义:混合项
+ PE₆·PE₇         ← ④纯位置:这两个位置的距离信号(第四章的主角)
```

**要点:位置信息没有因为"先加到一起"而消失**——它只是藏进了 ②③④ 项。之前"合并了就没了"的担心,是因为把向量当单个数字;用分配律一展开,四项各自归位。

(一个提醒:这里 w₆、PE₆ 都是 256 维向量,不是数字;"·" 是点积,不是普通乘法。展开规则 (a+b)·(c+d) = a·c + a·d + b·c + b·d 对向量点积照样成立。)

## 第四章 关键性质:第④项只依赖距离(绝对位置自动消掉)

这一章的主角是上一章展开的④ $PE_p·PE_q$。它为什么只依赖位置差?先看**单一频率对**——回忆 0.1 的点积定义和高中公式"和差化积":

```
( sin(θp), cos(θp) ) · ( sin(θq), cos(θq) )
= sin(θp)·sin(θq) + cos(θp)·cos(θq)      ← 点积:对应位置相乘再相加
= cos(θ(p−q))                              ← 和差化积:cosαcosβ+sinαsinβ = cos(α−β)
```

**这一步是关键**:左边看起来同时依赖 p 和 q 两个位置,右边只剩它们的差 p−q。

把所有频率对(128 对)都这样处理并相加:

```
PE_p · PE_q
= [sin(θ₁p)sin(θ₁q) + cos(θ₁p)cos(θ₁q)] + [sin(θ₂p)sin(θ₂q) + cos(θ₂p)cos(θ₂q)] + ...
= cos(θ₁(p−q)) + cos(θ₂(p−q)) + ... + cos(θ₁₂₈(p−q))
= Σᵢ cos(θᵢ·(p−q))
```

**结论:$PE_p·PE_q$ 的值只取决于 p 和 q 相隔多远,不取决于它们各自在哪。** 实测验证(d=8,即 4 个频率对,8 个位置的两两点积矩阵):

```
[[4.00 3.54 2.56 1.96 ...]    行 0:位置 0 与 各位置 的点积
 [3.54 4.00 3.54 2.56 ...]    行 1 = 行 0 整体右移一格
 [2.56 3.54 4.00 3.54 ...]
```

每条斜线上的值相同 → 点积只由距离 |p−q| 决定,比如 PE₆·PE₇ = PE₃·PE₄(都是距离 1)。

## 第五章 频率:同一列里位置在变,频率是"列"的属性

有人会困惑:sin(θp) 的 p 一固定就是一个数,怎么扯上频率?——**频率不是某个数的属性,是"这一列数值随位置起伏的节奏"**。把一列的值沿 p 画出来(60 个位置,值为正打 *):

```
θ = 1.0: .***...***...***...***...  (60 步起伏十几次 → 高频,周期 6.3 步)
θ = 0.2: .***************..........  (60 步才起伏两次   → 低频,周期 31 步)
```

物理里 x = sin(ωt) 的 ω 叫角频率,单位弧度/秒;这里变量换成位置 p,θ 就是"每走一格转多少弧度"(弧度/步)。**θ 由列号决定、全列恒定;p 是行号(token 位置),每行一个。** 一张表理清角色:

| 符号 | 含义 | 在 PE 矩阵里 | 谁决定它 |
|---|---|---|---|
| p | token 的位置(第几个词) | **行号** | 每个 token 一个 |
| i / θᵢ | 频率(这列波形多快) | **列属性** | 列号 i:θᵢ = 1/10000^(2i/d) |
| θᵢ·p | 相位 | 单元格输入 | 行号 × 列号共同 |

一整套递减的频率(θ 从 1 到 0.0001)像一整套尺子:高频列分辨近距(但几格就重复),低频列覆盖远距(但近距几乎无差别),合起来让任意合理的距离差都有唯一指纹。

**源码**:`model/position_encoding.py:12-25`

```python
pos = torch.arange(seq_len, dtype=torch.float, device=device).reshape(-1, 1)  # 行号:全部位置
idx = torch.arange(0, dim_model, 2, dtype=torch.float, device=device)         # 列号:偶数维下标
angles = pos / 10000 ** (idx / dim_model)    # 相位 θ·p:每个 2i 一个递减频率
pe[:, 0::2] = torch.sin(angles)              # 偶数列填 sin
pe[:, 1::2] = torch.cos(angles)              # 奇数列填 cos,与相邻偶数列同频
```

## 第六章 加性方案的软肋:给了原料,但要靠模型自己提取

第三章展开的四项,全都会进入注意力分数:

- ④(纯位置,只依赖距离)是**信号**
- ②③(词义 × 位置,与具体词有关)是**噪声**——它们干扰"这个位置差该得多少分"的判断

加性 PE 的处境:**距离结构(第四章)摆在输入里,但网络必须自己学出一套权重,把④放大、把②③压下去**。学得出来吗?通常可以。但这属于"给原料,不保证"——位置信号要和词义信号在同一向量空间里竞争,效果依赖训练。

这留给后人一个问题:**能不能不让模型费劲提取,而是把"只依赖相对距离"直接写进注意力公式?** 这就是下一章 RoPE 的出发点。

## 第七章 第二招:RoPE(旋转位置编码)——把距离直接做进公式

RoPE 的思路一句话:**让 query 向量和 key 向量各自按自己的位置"旋转",旋转后它们的夹角 = 位置差,点积天然只跟夹角(= 位置差)有关。**

### 7.1 直觉:旋转后,夹角 = 位置差

回忆第零章 0.5:旋转矩阵 R(p) 把向量转 p 弧度。

- token 在位置 p,它的 query 向量 q 被旋转 p 弧度 → q' = R(p)·q
- 另一个 token 在位置 p+k,它的 key 向量 k 被旋转 p+k 弧度 → k' = R(p+k)·k
- 旋转后,q' 和 k' 的**夹角 = (p+k) − p = k**,恰好是位置差!

(二维图示:位置 3 的 q 转了 3 弧度指向 3 点钟方向,位置 5 的 k 转了 5 弧度。两者夹角 2 弧度 = 位置差 2。位置 100 和 102 同理,夹角还是 2。)

### 7.2 逐步推导:为什么点积里绝对位置会消掉

现在算旋转后的点积,一共 4 步,**每一步都说明用了什么规则**:

**第 1 步:把点积写成矩阵形式**(用 0.2 的规则:左边转置 × 右边):

```
⟨R(p)·q , R(p+k)·k⟩ = ( R(p)·q )ᵀ · ( R(p+k)·k )
```

**第 2 步:对左边整体转置,用 0.4 的反序规则**(Mx)ᵀ = xᵀMᵀ:

```
(R(p)·q)ᵀ = qᵀ · R(p)ᵀ        ← 转置反序:q 从右边跑到左边,矩阵转置跟在后面
```

于是整个式子变成:

```
= qᵀ · R(p)ᵀ · R(p+k) · k
```

**第 3 步:用 0.5 的性质 B(R(p)ᵀ = R(−p)),把转置换成反向旋转:**

```
= qᵀ · R(−p) · R(p+k) · k
```

**第 4 步:用 0.5 的性质 A(旋转可合并),把相邻两个旋转矩阵合成一个:**

```
R(−p) · R(p+k) = R(−p + p + k) = R(k)        ← 先转 −p 再转 p+k,等于一次转 k
```

代入,完成:

```
⟨R(p)·q, R(p+k)·k⟩ = qᵀ · R(k) · k
                     ↑          ↑
                    原 query   原 key(不旋转的形态)
```

**绝对位置 p 在代数上消失了,只剩相对距离 k。** 不是模型"学会"忽略 p,而是公式结构上 p 自己消掉了——这是数学保证。

(数字验证可自己跑:q = (1,0),取 p=3、k=2。左边:先转 3 弧度再与转 5 弧度的 q 点积;右边:qᵀR(2)q = cos 2。两边都得 cos 2 ≈ −0.42。)

### 7.3 加性 PE 与 RoPE 对比

| | 加性 PE | RoPE |
|---|---|---|
| 位置注入方式 | embedding 后加一次指纹 | 每层注意力的 q/k 上乘旋转矩阵 |
| 位置项 | 藏在四项展开里,带②③混合噪声,靠网络滤 | 整个 q·k 只有距离依赖,数学保证 |
| 绝对位置 | 由网络学权重去抵消 | 代数上显式消掉 |
| 外推长序列 | 一般 | 好(可配合 YaRN/NTK 缩放) |
| 典型使用者 | 2017 原版、BERT/GPT-2 | LLaMA、Mistral、Qwen、DeepSeek |

**一句话:加法是"提供距离原料,让网络学";RoPE 是"把距离算好塞进公式"。**

### 7.4 RoPE 的代码改造点(对照本项目)

本项目没有 RoPE。若要加,不是在 encoder.py:83 换公式,而是在注意力投影之后插入旋转:

**源码**:`model/attention.py:47-57`

```python
def forward(self, query, key, value, mask=None):
    query = self.q(query)          # ← 在这里之后乘旋转矩阵 R(位置)
    key   = self.k(key)            # ← 在这里之后乘旋转矩阵 R(位置)
    ...
    attention, softmax_out = self.scaled_dot_product_attn(query, key, value, mask)
```

真实实现按频率对做"二维旋转"、`theta=10000` 频率表与第五章同一套思路——LLaMA 代码里的 `rotary_embedding` / `apply_rotary_pos_emb` 就是在做第七节这件事。

## 第八章 家族全景:位置编码不止这两支

| 方案 | 机制 | 谁在用 |
|---|---|---|
| 加性正弦(绝对) | 指纹相加进 embedding | 论文原版、本项目 |
| 学习式(绝对) | 位置查表,参数可训练 | BERT、GPT-2、OPT、ViT |
| **RoPE**(旋转) | q/k 旋转,分数只依赖距离 | LLaMA、Mistral、Qwen、DeepSeek、Gemma(开源主流) |
| ALiBi | 打分时按距离 |i−j| 减线性偏置 | BLOOM、部分 MPT |
| T5 式相对 bias | 按距离分桶学一组 bias | T5、FLAN |

时间线:2017 加法 → BERT/GPT-2 时代学习式略优 → 2021 RoPE 出现 → 2023 LLaMA 铺开后 RoPE 成默认答案。**RoPE 是主流,不是唯一**——看到配置里 `rotary`/`theta` 是 RoPE,`alibi` 是 ALiBi,都没有则是学习式或纯注意力。

## 附录 A:二维数值走查

词向量取 w₆ = (0.5, −0.8),w₇ = (1.2, 0.3)(任意假设);位置指纹 PE₆ = (sin 6, cos 6) ≈ (−0.279, 0.960),PE₇ = (sin 7, cos 7) ≈ (0.657, 0.754):

```
输入 a = w₆ + PE₆ = (0.221, 0.160)
输入 b = w₇ + PE₇ = (1.857, 1.054)

a·b = 0.221×1.857 + 0.160×1.054 = 0.579

展开核对(第三章的四项):
w₆·w₇     = 0.5×1.2 + (−0.8)×0.3     =  0.360   (①词义)
w₆·PE₇    = 0.5×0.657 + (−0.8)×0.754  = −0.275   (②混合)
PE₆·w₇    = (−0.279)×1.2 + 0.960×0.3  = −0.047   (③混合)
PE₆·PE₇   = (−0.279)×0.657 + 0.960×0.754 = 0.541  (④距离,= cos(7−6)=cos 1)
                                             ─────
                                       总计   0.579  ✓
```

注意 ④ = 0.541 = cos(1):距离 1 的两个位置的指纹点积直接等于 cos 1(第四章结论在 2 维下的实例)。

## 附录 B:本项目原实现的一个偏差(已修复)

原 `position_encoding.py` 频率写成了 `dim // dim_model`。当 `dim < dim_model` 时该式恒为 0,于是所有维度相位相同、只有一种频率——与论文的 `2i/d_model`(频率随维度递减)不符,位置指纹退化为互相复制的行。已替换为标准公式(第五章第二节代码),验证:列 0 相邻位置跳变 0.96(高频)、列 254 仅 0.0001(低频);奇偶列满足 sin²+cos²≡1。
